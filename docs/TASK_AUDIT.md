## 一、安全审计（最高优先级）

### 1. COM 高危面（本次最重要）
- `export_pages` 的每一道守卫是否**真的**能防止关掉用户的 PowerPoint？
  - 实现报告 D1 说：`DispatchEx` 在本机**不开新进程**，安全性实际全靠 `pre_count == 0` + POWERPNT.EXE 进程数守卫
  - **逐条审查这些守卫在异常路径下的行为**：Open 抛异常时、Export 中途失败时、finally 里的 Close/Quit 顺序
  - 特别查：**用户开着 PowerPoint 但没打开任何稿**（`pre_count == 0` 但进程存在）这个场景是否真被挡住
  - 特别查：**是否任何代码路径会写 `app.Visible`**（一旦写入会把用户窗口藏起来）—— 用 grep 独立确认，不要只看报告
  - 特别查：`Quit()` 是否可能作用到用户的实例上

### 2. 路径与文件安全
- pptx 输入路径、输出目录、底图文件名是否可能**路径穿越**（`..`、绝对路径、盘符、UNC）
- 主题名/文件名进路径前是否过滤（参照：本项目曾修过"项目名盘符逃逸（拦冒号）"）
- 临时目录的创建/清理是否安全（`shutil.rmtree` 的目标是否可能是用户目录？符号链接？）
- 输出文件覆盖策略（是否会静默覆盖用户已有文件）

### 3. 播放器 HTML 注入（高危面）
- `hl_anim.build_player` 的转义是否**等价或强于** `anim.py` 的纪律？
  - 三个上下文（HTML 文本 / 属性 / `<script>` 字符串）是否都处理
  - `</`、`<!--` 是否转义；占位符是否**单遍替换**（链式 replace 会被先前插入文本绕过 —— `anim.py` 曾因此出过 M2 审计项）
  - 找**反例用例**：构造能绕过的 title/路径，**实际生成 HTML 并检查**（别只读代码）
- 播放器是否引入新的同源风险？（`anim.py` 用 `iframe sandbox="allow-scripts"` 且**禁止** `allow-same-origin`；`hl_anim` 契约说不用 iframe —— 那它是否引入了等价或更弱的隔离？底图以 `file://` 还是站内路径加载？）

### 4. 上传/解析第三方 pptx 的风险面（若已有相关入口）
- zip bomb（超大解压比）、恶意 XML（XXE / billion laughs）、外部关系（`TargetMode="External"` 拉网络资源）、VBA 宏
- python-pptx 的解析是否会执行外链

## 二、代码审计

- **资源泄漏**：COM 对象、Playwright 浏览器/页面、文件句柄在异常路径是否释放
- **异常处理**：是否有裸 `except:`/`except Exception: pass` 吞掉真错误；错误信息是否泄漏敏感路径
- **静默失败**：是否有"算不出来就返回 0/空"而不报错的分支（高亮定位错了却不报错 = 最危险）
- **数值健壮性**：除零、负数、`None` 坐标、超长文本、EMU 溢出
- **与既有模块的关系**：是否重复实现了 `qa.py` 已有的能力（契约要求复用）；是否与 `anim.py` 的转义纪律分叉
- **测试质量**：实现者的 297 条测试是否有"永远通过"的假测试（断言恒真、mock 掉了被测逻辑、跳过条件过宽）

## 三、契约一致性

- 实现是否偏离契约？偏离是否**已在报告里申报**（申报过的算合规，未申报的算缺陷）
